# Gadget POS documentation

The documentation follows the software-development process rather than merely describing screens.

| Stage | Document | Purpose |
|---|---|---|
| Initiation | [Project charter](project-charter.md) | Problem, objectives, stakeholders, scope, and success measures |
| Requirements | [Requirements](requirements.md) | Functional and non-functional requirements and business rules |
| Design | [Architecture](architecture.md) | Structure, module responsibilities, interfaces, and deployment |
| Modeling | [Diagrams](diagrams.md) | Context, sequence, class, state, and deployment diagrams |
| Decisions | [Architecture decisions](decisions/README.md) | Why important technical choices were made |
| Verification | [Traceability](traceability.md) | Links requirements to design, implementation, and tests |
| Operation | [Getting started](getting-started.md) | Run the system locally |
| Configuration | [Configuration](configuration.md) | Supported environment, business, and device settings |
| Deployment | [Deployment](deployment.md) | The deliberately small Docker deployment model |
| Quality | [Testing](testing.md) | Test strategy and commands |
| Team workflow | [Contributing](../CONTRIBUTING.md) | Definition of done and contribution rules |

Diagrams and requirements must be updated in the same change as the behavior they describe.
